# 路书 · Web 版自驾行程规划

一个面向国内自驾游的行程规划（路书）工具：按「天」组织路线，逐点添加每天的地点，自动测算相邻地点间的车行距离并在地图上绘制导航线路，多用户管理与多天行程概览。

- **正式在线演示**：[https://lushu.tangletang.top](https://lushu.tangletang.top)
- **自动化部署**：基于 GitHub Actions CI/CD，代码推送至 `main` 分支全自动构建并热重载发布至腾讯云。

当前为**多用户版**：用户名密码注册登录，路书存服务端按用户隔离；管理员在后台统一配置地图 API。

## 快速开始

```bash
npm install
npm run server     # 启动服务端（多用户 + 管理后台，默认 http://localhost:3000）
npm run dev        # 前端开发服务器 http://localhost:5173（/api 代理到 3000）
```

- 打开 http://localhost:5173 ，注册用户名密码即可使用；**第一个注册的用户自动成为管理员**
- 管理员在右上角「⚙ 后台」配置高德 Key / 安全密钥 / 默认数据源，对全部用户生效；不配置则使用开源地图（免 Key）
- 路书数据保存在服务端 `server/data/db.json`（含密码哈希与会话，已在 .gitignore 排除）
- 生产模式：`npm run start`（构建前端并由服务端在 3000 端口统一托管）

## 地图数据源

- **🌍 开源地图（默认，免 Key）**——Leaflet + OpenStreetMap 瓦片，车行线路/距离用 [OSRM 演示服务](https://router.project-osrm.org)，POI 搜索/逆地理用 [Nominatim](https://nominatim.openstreetmap.org)。国内地点数据较稀疏；OSRM 演示服务与 Nominatim 有使用频率限制，已内置请求间隔与失败重试。
- **🇨🇳 高德地图（正式模式）**——数据与搜索质量更好。由管理员在后台配置 Key（类型须为「Web端(JS API)」，2021-12-02 后申请的需一并填入安全密钥 jscode）；正式部署请在高德控制台为该 Key 配置域名白名单。配置后用户可在顶栏一键切换。

> ⚠️ 两种地图坐标系不同（开源 WGS-84 / 高德 GCJ-02）。切换数据源会清空线路缓存并重算，请勿混用。

## 已实现功能（M1）

- **路书列表首页**：多路书管理——列表卡片（标题 / 日期 / 天数 / 总里程 / 更新时间）、创建新路书、删除（带确认）、按最近编辑排序；旧版单路书数据自动迁移
- **多天路书**：创建（名称 / 出发日期 / 天数），天数随时增减，删除有确认
- **逐点添加的日程**：每天就是一个有序地点列表，无固定起点/终点，也没有多余设置项——底部一个「＋ 添加节点」按钮，点开卡片**在卡片内搜索**并选择地点即完成添加；每个节点可随时点 ✏️ 进入自己的编辑卡片（改名 / 重新搜索更换地点）；自动算出与上一地点的行车距离；最后一个地点通常是当晚住宿
- **跨天自动接续**：次日的路线默认从前一天最后一个节点出发（可一键改为从本日第一地出发）
- **多用户**：用户名密码注册 / 登录（bcrypt 哈希 + 服务端会话），路书按用户隔离存在服务端；第一个注册的用户自动成为管理员
- **管理后台**：配置高德 Key / 安全密钥 / 默认数据源（对全部用户生效）、查看用户列表；未配置高德时仅开源模式
- **路书列表首页**：多路书管理——卡片（标题 / 日期 / 天数 / 更新时间）、创建、删除（带确认）
- **日期手风琴**：每天一节，头部显示当天起终城市摘要，可收起 / 删除 / 单独定位到地图；底部「＋ 增加一天」
- **竖向时间轴**：编号圆点 + 导航线路连线，节点下显示到下一地点的车行距离；悬停出编辑 / 删除
- **全屏选点页**：上搜索、背后地图——搜索结果以编号标记显示，点标记或点地图任意位置完成新增 / 替换；城市可搜索筛选；修改时自动带入原地点与城市
- **拖拽排序**：整行拖动调整顺序，完成后自动重算受影响路段
- **车行线路与距离**：相邻节点逐段调 OSRM / 高德 Driving，返回真实驾车距离与线路折线（坐标对缓存、间隔重试、失败回退直线并标注）
- **地图展示**：单日显示当天起终与序号；总览全程统一编号（起 → 1..N → 终），右上角「🗺 地图」看全程，每天标题地图图标看单日
- **总览页**：列出每天全部地点；行程设置（名称 / 出发日期 / 天数）与导入 / 导出 JSON、删除
- **响应式**：PC 左面板 + 右地图；移动端地图收起，「🗺 地图」按需全屏
- **地点类型与停留**：点地点名称进入编辑，可改名称、类型（途经 / 景点 / 餐饮 / 加油充电 / 住宿）和停留时长；新增地点时可先选类型，景点、餐饮等自带默认停留
- **每日时间表**：每天可设出发时间，按逐段车程 + 中途停留推算每个地点的预计到达时刻；单日驾驶超过 8 小时、预计 22:00 后到达时给出提醒
- **费用估算**：按车行里程和车辆能耗（燃油 L/100km 或纯电 kWh/100km、单价）估算油费 / 电费；高德模式下读取驾车结果自带的过路费（开源地图不提供）
- **全程合计与每日对比**：总览页显示总里程、驾驶时长、油费 / 电费、过路费，以及每天里程与驾驶时长的对比条
- **视频分享链接**：在「分享与导出」里「录制并分享」（或上传之前导出的视频），生成的链接只能观看这段巡游视频，不含路书内容、地点、地图配置和账号信息；关闭链接或删除路书时服务器上的视频随即删除。视频存放在 `server/data/videos`，单个最大 300MB，反向代理需放开上传大小（Nginx `client_max_body_size`）
- **一键导航**：每段路旁的「导航」可唤起高德或百度地图 App（网页版兜底），按当前数据源传对应坐标系
- **沿途补给**：搜终点附近住宿，以及沿车行路线的加油站、充电站、服务区，一键插入当天（自动放在绕路最少的两站之间）；开源模式用 Overpass（OSM 数据），高德模式用周边搜索
- **天气**：今天起 16 天内的行程日显示终点天气（Open-Meteo，免 Key）
- **导出**：长图（发朋友圈 / 小红书）、GPX 轨迹（WGS-84，可导入车机与户外 App）、ICS 日历（每天一个日程）、JSON
- **巡游回放与视频导出**：按时间轴播放（全景开场 → 逐段行驶、到站停留 → 拉回全景收尾，每段时长按 √里程压缩、起步加速到站减速）；分段取景 / 跟随 / 全景三种镜头，段间 flyTo 过渡；路段说明卡、里程表、到站站牌与开场 / 片尾标题卡；可录制为 16:9 视频。节奏与镜头思路借鉴 [map-motion](https://github.com/SpaceZephyr/map-motion)

## 技术栈

- 前端：Vue 3 `<script setup>` + TypeScript + Vite + Pinia + vuedraggable
- 地图：双数据源（`services/map.ts` 统一调度）——开源 Leaflet + OSRM + Nominatim；高德 JS API 2.0（Driving / PlaceSearch / Geocoder / Geolocation）
- 服务端：Node + Express + bcryptjs，JSON 文件存储（`server/data/db.json`），会话 token 鉴权

## 关键设计说明

- **坐标系**：坐标随数据源而定——开源模式为 **WGS-84**，高德模式为 **GCJ-02**。切换数据源会清空线路/距离缓存并按新数据源重算，避免混用偏移。
- **Key 安全**：高德 Key 由管理员配置在服务端，前端 JS API 使用（该 API 本身如此），通过域名白名单防护；开源模式无需任何 Key。
- **配额控制**：搜索防抖、逐段线路按坐标对缓存、请求间隔 + 失败重试；OSRM / Nominatim / 高德均为公共服务，注意用量。
- **数据**：路书自动保存到服务端；导出 / 导入 JSON 可在用户间迁移（导入即新增一本路书）。

## 已知限制

- 过路费仅高德模式可得；油费为按里程的估算值
- 沿途补给在开源模式下依赖 Overpass 公共服务，国内 POI 覆盖不全且有频率限制
- OSRM / Nominatim 为公共演示服务，仅适合开发测试，生产环境需自建或换商用服务
- 数据库为单文件 JSON，适合个人 / 小团队；需要大规模并发时建议换 SQLite 或其他数据库
